# 股票模拟仓多智能体方案：分层作战 + 事件溯源 + 信用分演进

> 状态：提案（待评审）· 2026-10-11 立项
> 源头：主人抛砖引玉的七组方案（大盘预测/热点题材/买进/卖出/模拟盘/操作/数据），
> 本文给出修订版架构——目标：**100 万本金模拟盘资产持续升值，可回溯、可演进、可升级**。

## 目标与判据

- **资产持续升值**：控制回撤优先于追逐收益（活下去 > 跑得快）；
- **可回溯**：任意一天的任意一笔盈亏，可沿因果链追查到产生它的情报与组别；
- **可演进**：各组贡献有量化记账，决策权重随实绩动态调整；
- **可升级**：策略变更先回测、再影子并行、跑赢才上线，永不在主组合上裸奔试错。

## 对原七组方案的四个结构性修正

1. **买进组与卖出组合并**。买卖是同一问题的两面：「100 万此刻如何配置最优」。
   分开必然打架（买进要买 60 万、卖出只批卖 20 万，现金缺口无人裁决）。
   修订：**组合管理组（PM）输出目标持仓表，订单 = 目标持仓 − 当前持仓的差分**。
   加仓/减仓/清仓全是同一动作的特例，资金自动平衡。
2. **操作组不是智能体，是代码**。模拟环境的「下单」= 模拟交易所规则
   （T+1、涨跌停、集合竞价、手数、费用、滑点）。确定性规则必须由撮合引擎 +
   账本代码承载——LLM 会在涨停板上「善意成交」买单，幻觉直接污染账本。
   确定性账本同时是可回溯的地基：任意一天可逐笔重放。
3. **补两个组：风控与归因**。没有独立风控的一票否决，「持续升值」退化为
   「持续满仓追涨」；没有归因记账，「可演进」无从谈起——不知赚的钱是谁的
   功劳，升级等于瞎改。
4. **15 分钟全员轮询改为事件驱动**。本地模型容量有限（50k tokens 单程 40s 级），
   七组每 15 分钟全员出动 × 长上下文，延迟成本双爆炸；且盘中值钱的是**事件**
   （放量异动、开板、指数破位），不是整点。A 股 T+1 决定盘中预测的价值在择时
   （入场价、持仓卖出时点），不在方向高频重估。轮询只保留盘前/午评/盘后三个
   低频时点。

## 分组架构（九组 + 一个调度器）

组内结构沿用「组长 + 组员」：**组员是并行专项分析员（各看一个视角），组长仲裁聚合出组结论**。
组间只流转结构化情报单据，不流转自由文本。

| 层 | 组 | 职责 | 组内分工 |
|---|---|---|---|
| 情报层 | ① 市场环境组（原大盘组改造） | 输出**市场状态分类**（趋势上行/震荡/退潮/恐慌）+ 波动率估计 + 关键位——不预测点位（命中率低且不可操作），状态分类直接决定仓位区间与策略切换 | 指数技术面 / 资金面（成交额、两融、北向）/ 情绪面（涨跌家数、连板高度、炸板率） |
| 情报层 | ② 题材挖掘组 | 当日热点 + **生命周期判断**（首日发酵/主升/高潮/退潮）+ 龙头辨识 + 持续性评分 | 新闻舆情 / 涨停梯队复盘 / 板块资金流 |
| 情报层 | ③ 个股研究组（可选，P2 后启用） | 持仓股与候选股个体分析：公告、龙虎榜、技术形态 | 按持仓/候选分片 |
| 决策层 | ④ 组合管理组 PM（合并原买进/卖出/模拟盘决策职能） | 输入情报 + 当前持仓 + 风控约束，输出**目标持仓表**（目标权重 + 理由引用 + 紧迫度） | 组长制，单点决策 |
| 决策层 | ⑤ 风控组（独立，有否决权） | 硬约束由代码先挡，智能体做软判断（「题材已高潮三天，追高性价比差」） | 单员即可 |
| 执行层 | ⑥ 撮合引擎 + 账本（**纯代码，无 LLM**） | A 股规则全家桶；出成交回报与每日结算单 | — |
| 进化层 | ⑦ 归因复盘组 | 每笔盈亏沿因果链回溯到信号与组别，维护**各组信用分**（分市场状态记账：牛市里题材组准、震荡市里环境组准） | 日账员 / 周报员 |
| 进化层 | ⑧ 策略演化组 | 每周据归因报告提案；改动先回测、再跑**影子组合**（同行情新旧策略并行两本账），跑赢才上线 | 单员即可 |
| 数据层 | ⑨ 数据提供组（现有 3 个智能体） | 行情/新闻/基本面数据供给 + **数据质量自检**（缺失/延迟/复权口径），坏数据敢告警不静默 | 维持现状 + 自检职责 |
| — | 调度器（纯代码，xusi 侧） | 时间轴编排、事件路由、超时看门狗（所有组间调用带超时+心跳+重试预算——daemon 假活有前科） | — |

## 信息流：三类单据 + 事件溯源日志

### 情报单（情报层 → PM）

```json
{
  "signal_id": "sig-20261011-014",
  "group": "theme",
  "group_version": "theme-v1.3",
  "subject": "固态电池",
  "view": "首日发酵，龙头 X 放量首板，板块内 5 家涨停，持续性评分 7/10",
  "confidence": 0.65,
  "horizon": "1-3d",
  "invalidation": "若龙头 X 次日竞价低开超 3% 或板块涨停家数<2，本判断作废",
  "evidence": ["news://...", "quote://sh600xxx/20261011"],
  "issued_at": "2026-10-11T08:42:00+08:00"
}
```

**`invalidation`（证伪条件）是灵魂**。有了它，归因才能区分「看错了」（扣信用分）
与「看对了但前提变了」（不扣）。没有证伪条件的情报不允许进入 PM 输入。

### 决策单（PM → 风控 → 引擎）

```json
{
  "decision_id": "dec-20261011-003",
  "ref_signals": ["sig-20261011-014", "sig-20261011-007"],
  "target_positions": [
    {"symbol": "sh600xxx", "weight": 0.08, "urgency": "open_auction", "reason": "题材龙头首板接力"},
    {"symbol": "sz300yyy", "weight": 0.00, "urgency": "intraday_event", "reason": "破位止损"}
  ],
  "cash_floor": 0.20,
  "valid_until": "2026-10-11T10:30:00+08:00"
}
```

目标权重制：weight=0 即清仓，买卖统一。`valid_until` 防止过时决策被执行。

### 订单/成交单（引擎内部 → 账本）

```json
{"order_id": "ord-...", "decision_id": "dec-20261011-003", "symbol": "sh600xxx",
 "side": "buy", "qty": 2000, "limit_price": 18.50, "ts": "..."}
{"fill_id": "fil-...", "order_id": "ord-...", "price": 18.42, "qty": 2000,
 "fee": {"commission": 9.21, "stamp_tax": 0, "transfer_fee": 0.37},
 "slippage_vs_open": -0.004, "ts": "..."}
```

### 因果链与日志

全链路 `signal → decision → order → fill → outcome` 用 ID 串联，落
**append-only 事件日志**（每事件一行 JSON，只增不改），外加每日快照
（持仓/现金/净值/市场状态）。**可回溯 = 事件溯源**：任意一天从快照+日志完整
重放；任意一笔盈亏沿链追查到具体情报与组别版本。

## 撮合引擎规则清单（A 股模拟）

| 规则 | 取值/语义 |
|---|---|
| 交易时段 | 集合竞价 9:15–9:25（9:20 后不可撤单）；连续竞价 9:30–11:30、13:00–15:00 |
| T+1 | 当日买入次交易日方可卖出；当日卖出资金当日可用（可再买） |
| 涨跌停 | 主板 ±10%，创业板/科创板 ±20%，ST ±5%，北交所 ±30%；**涨停买单不成交**（排队，开板才按时间优先成交），跌停卖单同理 |
| 手数 | 100 股整数倍（科创板 200 起、1 股递增）；卖出零股一次性出清 |
| 费用 | 佣金万 2.5（最低 5 元，双边）；印花税卖出 0.05%；过户费 0.001%（沪市） |
| 滑点 | 买单成交价 = min(限价, 对手价 + 冲击成本)；单笔成交量 ≤ 该分钟 bar 成交量的 10%，超出部分下一 bar 续撮 |
| 停牌/一字 | 停牌不可交易；一字涨停买单全天排队不成交（除非开板） |
| 禁买清单 | ST（风控默认）、退市整理期、上市 <5 日新股、停牌 |

撮合引擎只认行情数据与规则，不认任何智能体的「解释」——**账本的权威性来自
代码的确定性**。

## 一天的时间轴

- **08:30 盘前**：数据组刷隔夜（外盘/公告/新闻）→ 环境组 + 题材组出晨报 →
  PM 出**预案**（条件分支而非死订单：「低开 >0.8% 则…；某题材竞价异动则…」）→
  风控审核 → 9:20 前定竞价决策单 → 9:25 后按撮合结果修正当日计划
- **09:30–15:00 盘中**：事件驱动。数据组监听异动（涨速/放量/开板/指数穿位）
  推给相关组；PM 只在事件触发或持仓触及预案条件时召解决策；**硬熔断由代码
  实时执行**（如单日浮亏 >3% 强制降仓至仓位下限，不经过任何 LLM）
- **15:00 盘后**：结算 → 归因组出当日账（信号命中率、执行滑点、各组贡献）→
  入知识库
- **周末**：演化组周会——归因周报 → 提案 → 回测 → 影子组合排期

## 「三可」的实现机制

### 可回溯
事件溯源日志 + 每日快照。支持：按日重放（审计某天每笔成交的依据）；
按信号追查（这个情报最终赚了还是赔了）；按版本追查（某版 prompt 上任后
表现曲线）。

### 可演进：信用分

- 每个情报在 horizon 到期后按结果计分：方向对且未被证伪 → +，错 → −，
  触发 invalidation → 0（不计入）；
- 信用分**分市场状态记账**（同一组在趋势市与震荡市分开计），滚动窗口 60 交易日；
- PM 参考各组情报时按信用分**动态加权**——信用分不进风控硬规则，只影响
  情报在决策中的话语权；
- 各组 prompt/配置全部**版本化**（`group_version` 进情报单），归因记到版本
  头上，差的版本有数据支撑地淘汰。

### 可升级：变更流水线

```
提案（演化组） → 历史回测 → 影子组合并行 ≥2 周 → 跑赢主组合才替换 → 版本号递增
```

影子组合共享同一撮合引擎，只是另一本账，几乎零成本；任何时刻可并行多个
影子组合做 A/B。主组合的每次策略变更都有完整审批链（提案→回测报告→影子
战绩→上线时间戳）。

## 风控规则初值（可调，调整也走变更流水线）

| 规则 | 初值 |
|---|---|
| 单票仓位上限 | 10% |
| 单行业/题材集中度 | 25% |
| 总仓位区间 | 随市场状态浮动：趋势上行 60–90%，震荡 30–60%，退潮/恐慌 0–30% |
| 单日回撤熔断 | 组合单日浮亏 >3% → 代码强制降仓至区间下限 |
| 总回撤熔断 | 净值自高点回撤 >15% → 停止新开仓，演化组强制介入复盘 |
| 黑名单 | ST、退市整理、上市 <5 日、停牌、近 30 日有立案/处罚公告 |

## 与 xusi 基础设施的映射

- 每组 = 一个 agent 实例（组内组员 = 多实例并行），跑在 xusi 管理的容器/bare 运行时上；
- 组间通信走**邮箱投信**（情报单/决策单即信件载荷，JSON 附件）；
- 调度器是 xusi 侧代码：cron 时间轴 + 事件路由 + 超时看门狗；
- 账本与事件日志放 PM 实例 workspace（`workspace/stocksim/`），每日快照入档；
- 所有组间调用遵循「不干预 LLM 铁律」：调度器只投信与验收，绝不直接改 agent 状态。

## 落地阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 地基（纯代码，无 LLM）** | 撮合引擎 + 账本 + 事件日志，用假信号喂 | 历史一个月行情重放，手工单撮合结果与逐笔规则核对一致 |
| **P1 单线程闭环** | 数据组 → 环境+题材 → PM → 风控 → 引擎；只做盘前+盘后两个时点，盘中手动 | 跑通 5 个交易日，事件链完整可查 |
| **P2 事件驱动盘中** | 数据组异动推送 + 熔断代码 + 归因日报 | 盘中事件触发到成交回报 <10 分钟；日报自动产出 |
| **P3 演进闭环** | 信用分加权 + 影子组合 + 演化周会 | 第一个策略变更走完整流水线（提案→回测→影子→上线） |

P0 是全部的地基——规则做不扎实，上面九组全是空中楼阁。
