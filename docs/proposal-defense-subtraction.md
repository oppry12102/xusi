# 防线的本质是信息——v2.9.41 六机制减法方案（内核修改建议）

> 状态：**建议（待评审）** · 2026-11-22 · 源头：提交 `bd47021`（v2.9.41，+56/−4 行）代码审查 15 条确认发现
> 本文回答三件事：①为什么 15 条发现不该逐个修；②六个机制各自的本质形态是什么；③哪些取舍是明知的。

## 1. 诊断：15 条里约 10 条不是笔误，是机制×机制的交互伤

v2.9.41 加了六个机制（三次拒绝、GatewayCtxReject、手写原子写、读端容错、
字节码禁令、shell umask），审查确认 15 条发现。按伤的性质分：

| 机制 | 伤到了谁 | 发现 |
|---|---|---|
| 三次拒绝（worker 线程内 log） | breath 原子写（8 并发写者共享固定 tmp 名，实证 ~6% 撕裂） | #1 |
| 三次拒绝（在校验前开火+文案未核实） | 大脑的信息面（「未知工具」等可行动错误被掩盖；「结果相同」从未比较——**防线自己撒谎**） | #3 #9 #15 |
| GatewayCtxReject（刮网关 body 散文） | 故障转移（直连脑连坐/漏匹配则全池重发）、异常分类学（未标 abnormal→假事实+600s）、错误契约（raw body 入账）、状态推导（next_wake_at 落在过去） | #4 #5 #6 #7 #8 #10 |
| 手写 tmp+os.replace | 「每物一窝、单写路径」（`facts._atomic_json` 自称唯一写法，同文件 103 行在用） | #11 |
| 读端容错 breath_unreadable | 状态诚实（把 TOCTOU 的 FileNotFoundError 谎报成 running_session；它防的半写已被同提交原子写消除） | #2 #14 |
| 字节码禁令 / shell umask | 子进程性能税（每次 +0.1~0.6s）/ 裸机无权限基线 | #12 #13 |

逐个修补 = 机制还在、伤被盖住，且每个补丁又生新的交互面。宪法单一否决测试
逐条过一遍，答案很清楚：

> **「该不该再执行这条命令」需不需要理解使命/意图？需要 → 归大脑。**
> 等待外部数据的轮询与卡死循环，指纹上不可区分——区分它是语义判断。
> 机器的机械职责只剩「递」：把「第 N 次了、结果没变」这个事实递给大脑。

三次拒绝让机器做了语义判断（更像第二个大脑），GatewayCtxReject 赌了第三方
内部行为（网关文案不变、前 400 字符、大小写——「换掉它其余不动」不及格），
读端容错让机器谎报状态。三条都直接撞宪法；手写原子写撞「复用现成机制」。

## 2. 核心论据：生效的是那句话，阻断零收益

提交自己的证据是「对照实验 3/3 模型**看到文案后**改道」——生效机制是
**LLM 读到的信息**，不是「不执行」这个动作。而阻断侧：

- 大脑不理会文案时，拒绝循环（调→拒→再调→再拒）与执行循环**同速率烧
  token**——拒绝并不止损，只是信息更少（工具的自身错误被掩掉，#3）；
- 大脑理会文案时，批注与拒绝等效——改道的决定本来就是大脑做的。

两种防线同以文案为生效机制，批注式严格占优：信息持续流动（唯一可能破循环
的东西），校验错误自然露出，文案只陈述实测事实、不可能撒谎。这正是法律条
「能让 LLM 做就让 LLM 做」的本义：机器的防线退化为一行真话，判断归大脑。

## 3. 修法逐条

### 3.1 三次拒绝 → 主循环批注（agent.py）

把检测从 worker 线程的 `_exec`（373-391）**移到收集循环**（445 行起，
单线程、结果在手），改「拒绝执行」为「照常执行 + 结果尾部批注」：

```python
# 收集循环内、content_str 定稿后、messages.append 前：
fp = fn + "\x00" + (tc.get("arguments") if isinstance(tc.get("arguments"), str)
                    else json.dumps(tc.get("arguments"), ensure_ascii=False, sort_keys=True))
digest = hash(content_str)
_cmd_repeat = _cmd_repeat + 1 if (fp, digest) == _last_sig else 1
_last_sig = (fp, digest)
if _cmd_repeat >= 3:
    content_str += (f"\n[机器批注] 此命令已连续执行 {_cmd_repeat} 次且结果相同。"
                    "若在等待外部数据，请 end_session 预约唤醒；若预期结果应变化，"
                    "请检查依赖或换方法。")
    log({"event": "tool_repeat_note", "tool": fn, "n": _cmd_repeat,
         "args": tc.get("arguments"), "at": iso()})
```

一并消解四条：

- **#1（并发撕裂）**：`log()` 回到主线程，events.py「发布者只有 daemon 单
  线程」不变量恢复——breath 原子写的多写者问题在**根源**消失，不需要任何
  锁或 tmp 唯一化补丁；
- **#3（撒谎/掩盖）**：批注在执行**之后**附加，「未知工具」、参数校验错误
  照常抵达；「结果相同」现在是真的比较过（digest）才说，N 只计已执行次数；
- **#9（name=null TypeError）**：指纹构造离开 `_exec`，缺 name 的畸形 call
  照旧走既有「畸形 function_call」错误槽，不新增异常面；
- **#15（事件无参数）**：`tool_repeat_note` 带 args，且不再有 `refused`
  状态从日志分支漏网。

并行批 3 个相同调用：全部执行（结果本来可能各不相同），批注落在第 2、3 个
的尾部——语义干净，因为比较的是**已完成的结果**。

### 3.2 GatewayCtxReject → 整体删除，契约归网关（llm.py、agent.py）

删除：`GatewayCtxReject` 类（llm.py:35-38）、body 刮标记（llm.py:379-381）、
FailoverBrain 特例（llm.py:482+）、agent.py 的捕获分支（300-302）。
网关拒绝回到普通 HTTP 错误老路：RuntimeError → 池内轮换 → 全灭则
llm_error 收场——异常分类学、120s 平间隙安全网、事实记账全是走熟的路，
#4 #5 #6 #7 #8 #10 六条随机制消失。

论证删除而非修补：

- **它防的烧 token 基本不存在**：网关熔断发生在生成**之前**，被拒请求成本
  ≈0；池轮换把同一上下文重发给同网关后的各脑，每个都是立即 4xx，总成本
  有界且微小——与工具循环的 6.4 亿 token 不是一个量级；
- **它赌第三方内部行为**：body 前 400 字符、文案拼写、大小写。宪法「不赌
  第三方内部行为」直接否；
- **真契约是头部**：提交自己 defer 的 X-Ctx-Warn 消费才是解耦形态
  （`X-Ctx-Reject: ctx_loop|ctx_fuse` + 专用状态码）。按项目惯例「有实证
  案例再补」——网关契约落地那天再补，内核今天不该刮散文。

### 3.3 breath 原子写 → 复用 `facts._atomic_json`（daemon.py）

183-193 的手写 tmp+os.replace 收敛为一行：

```python
facts._atomic_json(get_config().breath_path,
                   {"at": iso(), "at_epoch": time.time(), "session_id": sid})
```

`facts.py:52-56` 自称「机器事实文件的唯一写法」，daemon.py:103 本就在调用
——同一惯用法只留一个拼法（#11）。3.1 把写者收回单线程后，这就是全部所需。

### 3.4 读端容错 → 整段删除（api/app.py）

删 109-117 的内层 try/except，恢复原代码。它防的「半写」已被同提交的原子写
消除；剩下的 exists→read TOCTOU 竞态，**旧**外层 `except OSError` 本就正确
落到 session_end 推导状态——新分支反而把它谎报成 running_session（#2），
还破坏了 `out` 预声明全键的固定 shape（#14）。修写端就够，读端容错是给已
消除的问题加的、还会撒谎的保险带。

### 3.5 字节码禁令 → 建 venv 时预热（Dockerfile / entrypoint）

`PYTHONDONTWRITEBYTECODE=1` 保留（审跑分离不变量不动），在创建实例 venv 处
加 `UV_COMPILE_BYTECODE=1`（或一行 `python -m compileall`）——`py_compile`
不受该 env 抑制，预热合法。缓存在了，禁令的代价就是零（#12）。一行，不新增
机制。

### 3.6 umask → Python 入口一处（cli.py），删 entrypoint 三行

`os.umask(0o077)` 放在 serve/daemon 进程启动处——容器、裸机、任何安装形态
同一处生效（#13）。shell 侧三行删除。进程全局生效正是目的（数据面文件全部
0600）；若未来库化被嵌入他进程再议。

## 4. 取舍（明知的）

1. **批注文案未经对照实验**。拒绝文案的 3/3 改道是旧证据，批注文案需同款
   对照复跑一次（验收 §5.4）。理论上严格占优（§2），但实证传统不省。
2. **删 GatewayCtxReject 后，网关熔断场景靠池轮换兜底**。若某网关对拒绝
   请求也计费，或池内全脑同挂一个网关且拒绝有成本——那才是补头部契约的
   实证时机，且补的是头部不是 body。
3. **删读端容错后，breath 真损坏（非半写，如磁盘腐坏，ValueError 非
   OSError）将 500 响亮失败**。取「响亮优于静默」：观察台对监控撒谎比
   答不上来更危险。若想更稳，备选是外层同接 ValueError 落 error 态——
   二选一，本文取响亮。
4. **结果比较用 `hash(content_str)`**，结果驻留内存的一次哈希，成本可忽略；
   不持久化、不比正文，语义上「相同」= 序列化后全等。
5. **umask 是进程全局设置**，包括 webui 线程等——这正是目的；副作用面=
   数据面全部 0600，与容器现状对齐。

## 5. 范围与验收

行数预算：**删约 40 行、增约 10 行**，净 −30；15 条发现全部**消解**（机制
没了伤就没），零补丁。

selftest 补六组断言（契约打在真进程上）：

1. 同命令同结果连续 3 次：第 3 次**仍执行**（结果在场）且尾部含机器批注；
2. 未知工具连调 3 次：每次都拿到「未知工具」可行动错误，不被批注掩盖；
3. 并行批 3 个相同调用：全部执行，批注落在第 2、3 个尾部；并发压测下
   breath.json 零撕裂（钉住 #1 的回归）；
4. 网关 4xx 含标记串：走 llm_error 老路（failover 发生、120s 平间隙），
   无 GatewayCtxReject 类型残留（grep 级断言）；
5. breath 写路径只经 `facts._atomic_json`（grep 级断言）；breath 存在但
   读到 FileNotFoundError 时 /v1/status 落 session_end 推导状态；
6. 裸机 `serve` 启动后新文件 0600；容器内子进程冷启动时间回到基线。

三条单调箭头逐条过：

1. **机器语义职责不增**（减：执行权判断、网关策略探测都删了）✓
2. **大脑能力面不减**（宽：可行动错误不再被掩盖，信息只多不少）✓
3. **验证覆盖不变浅**（新增六组断言，含真进程并发压测）✓

关联：与 `proposal-no-silent-loss.md` 同族（机器不得对大脑说谎——#3 的
撒谎文案、#2 的谎报状态皆是）；宪法对照见 `constitution.md` §一（单一否决
测试）、§四（能让 LLM 做就让 LLM 做 / 不赌第三方内部行为 / 复用现成机制）。
