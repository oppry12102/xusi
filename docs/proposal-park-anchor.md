## 0. 一句话结论

v2.9.46 修对了进程内的病（e2e S5b），代价是把真值基线装进 `_park_n`、带过了一次迭代
边界。这是内核里一处丢了会改变唤醒行为的内存，而它丢失后的退路（末条 `session_end`）
在驻留路上丢成了**吞信**——v2.8.78 定的老规矩是「重启丢基线 = 噪声方向」。改法是减法：
删掉 `_park_n`，基线在哪就用在哪；开机时的账本锚从「末条收尾行」改为「上一口收尾行」。
空转呼吸不改。

|---|---|---|---|
| 1 | `_park_n` 是跨迭代内存；重启后的退路吞信 | **改（减法）** | 宪法 2/3；v2.8.78「丢基线 = 噪声方向」；§4 实测复现 |
| 2 | 回退 #37 后空转呼吸回来了 | **不改** | 平凡规则的价格；#37 的病根是需要证明的断言（§3） |
| 3 | e2e 两处注释错位 | **随 1 改** | 两行注释；提交说明已推送，不改历史 |

## 1. 诊断：一处代码被要求应付两种处境

唤醒基线 = 本口会话开始前的账尾 `_tail`，是 `_loop` 的迭代局部变量——随迭代生灭、
随进程生死（`opening-as-state.md` §二「报一次算数」）。普通休眠在同一迭代内用完即弃。
停机不同：要用它的那一口在**下一迭代**，于是 v2.9.46 让它活过迭代边界：

```python
_park_n: int | None = None                                   # daemon.py:251——循环之外，跨迭代
_anchor = _park_n if _park_n is not None else int((last or {}).get("n") or 0)   # daemon.py:277
```

（不能直接在循环顶用 `_tail`：`continue` 之后它是停机口**之后**的账尾，中途信被冒掉
——这正是 v2.9.46 引入 `_park_n` 的原因。）问题全在 `else` 那半句。这一行应付的其实是
两种处境，被压成了一处：

| 处境 | 手里有什么 | 现版用的锚 | 结果 |
|---|---|---|---|
| 刚停机（进程内） | 真值 `_tail` | `_park_n`（真值） | 对：一信恰一口呼吸 |
| 开机 / 重启 | 只有账本 | 末条 `session_end` 的行号 | **错**：停机那口会话中途未读的信落在锚之前，永久驻留 |

触发窗口很窄（停机口写下 `session_end` 到下一口开始之间进程死），但方向错了。同一
方向的洞这是第四次：v2.8.70（位点 = 收尾行）、v2.9.34（驻留两把锚）、v2.9.44 的 #37
（收尾锚）——收尾行把中途行冒掉。本次是它在重启路径上的残留。

## 2. 修法：基线在哪，驻留就在哪

两种处境分开写，各用各手里有的东西。新概念 0：`_tail`、`session_end` 行、`resume_stop`
都是现成的，新增的只是一个纯读函数的名字。

### 2.1 账本锚的唯一定义（daemon_facts.py）

```python
def park_anchor() -> int:
    """驻留唤醒锚（账本形态——开机/重启时没有会话前基线可用）：停机那口之前、
    上一口的收尾行号（没有上一口 = 0）。其后的信都算新：停机会话中途未读的信
    不吞；重启丢基线至多多唤一口（噪声方向），不丢信。"""
    ends = facts.since(0, type="session_end", limit=2)
    return int(ends[0]["n"]) if len(ends) > 1 else 0
```

与 `resume_stop` 同住同族：纯读、零副作用、不启 daemon 即可直测。锚从「末条收尾行」
（停机口自己的收尾，晚于中途信）改成「上一口收尾行」（早于停机口之内的一切行）。

### 2.2 daemon.py：删 `_park_n`，两处各归其位

```diff
-        _park_n: int | None = None
 ...
                 last = daemon_facts.last_result()
-                _anchor = _park_n if _park_n is not None else int((last or {}).get("n") or 0)
+                _anchor = daemon_facts.park_anchor()
                 if daemon_facts.resume_stop(last) \
                         and not facts.since(_anchor, type="mail", limit=1):
                     self._sleep_until(math.inf, hear_bell=False, since_n=_anchor)
                     continue
-                _park_n = None
 ...
                 if result.get("stop_requested"):
-                    _park_n = _tail
+                    if not facts.since(_tail, type="mail", limit=1):
+                        self._sleep_until(math.inf, hear_bell=False, since_n=_tail)
                     continue
```

| 处境 | 在哪 | 锚 | 性质 |
|---|---|---|---|
| 刚停机 | 停机分支（`_tail` 所在的迭代内） | 会话前账尾 `_tail` | 真值——与休眠同一条规则；会话中途有信就不在此驻留，回循环顶当场给一口（S5b） |
| 开机 / 重启 | 循环顶 | `park_anchor()` | 账本近似——只会更保守，至多多一口 |

循环顶每次迭代都过一遍：开机/重启时它是唯一的驻留判定；分支驻留被信唤醒之后它只是
复查（此刻必有新信，照常给一口）。

**不变式**（写进注释）：循环顶的锚 ≤ 分支里的锚（上一口收尾行 ≤ 本口会话前账尾）。
方向是关键——分支里能唤醒的信，循环顶必不拦。v2.9.34–v2.9.45 的洞是反方向：分支按
会话前锚唤醒，循环顶按收尾行再驻留，信被吞。本方案里循环顶只比分支**更愿意醒**。

**按五个角度**：

- **有状态变无状态 / 解耦**：`_park_n` 删除，daemon 回到零跨迭代状态。刚停机那条路
  不依赖账本历史，开机那条路只依赖账本。`daemon.py` 模块头「内存不存跨迭代关键状态」
  重新为真，一字不用改。
- **简单**：新概念 0。驻留从一处变两处，但那是两种真实处境各归其位，不是同一件事写两遍。
- **不为安全过度设计**：没有为这个洞加任何防线——只是把已有的退路从「静默」换成「多一口」。
- **让 LLM 做**：多出的那一口只在重启后出现，大脑读账无新事、一句收工。

## 3. 不改：空转呼吸（第 2 点）

**是什么**：会话中途到达的信/铃，哪怕大脑当场已办结，收尾后仍立刻再唤一口——
`sleep_seconds` 实际被绕过。v2.9.44 的 #37 想消掉它，v2.9.46 回退，价格回来了。

**为什么是价格不是缺陷**：机器的规则是「基线之后有行就醒」。这条规则**平凡为真**——
陈述的是机械事实（行号比较），不需要证明。#37 把基线挪到收尾行，等于多陈述了一句
「收尾前的行都已办结」——这需要证明（机器不知道大脑读没读），S5 一跑就倒。按
`proposal-trivially-true.md` §1 的测试：凡需证明的断言，都是未来的发现。

**要消掉这个价格只有三条路，每条都要加一个概念去省一口短会话**：

| 路 | 做法 | 先例 / 代价 |
|---|---|---|
| 大脑报读账水位 | `end_session(read_n=…)`，机器比行号 | 即 v2.8.77「位点归大脑」的游标，v2.8.78 以「机器不记、不问、不催」退役；改 `end_session` 参数面 |
| 机器记已递到第几行 | 在工具结果路径上记账 | 即位点簿记，v2.8.70 整层删除（「三份手写去重/位点，语义各异，第三轮审查已错两次」）；agent 循环要知道 facts 工具结果的形状 |
| 出口处递一次 | `end_session` 时若有未告知的新行，退回一次并告知 | 新机制；改 `end_session` 契约（可能被退回一次） |

「能让 LLM 做」在这里的落点是：读没读、办没办是大脑的判断，机器不该问，也不该替它记。
**大脑这边今天已经能做**：系统提示如实写着「含会话中途到达的——收尾后本机当场再唤」
（`agent.py:73-74`），被空唤时读账无新事、一句收工即可。

**什么时候才值得动**：有实证显示空唤占了可观成本。`early_wake` 行自带 `new_rows`
（`daemon_facts.py:180`），可以先量。到那时正解是第三条——机器递一句真话、读不读归
大脑——不是前两条。按项目惯例：有实证案例再补。

## 5. 没选的三个形态

| 形态 | 结果 | 不选的理由 |
|---|---|---|
| 单一规则：删 `_park_n`，循环顶一处驻留、只用 `park_anchor()` | 最简单（零内存、一处驻留）；S11 绿 | S11b 红：被信叫醒、读完再停机后又被唤一次——进程内违反「报一次算数」，大脑刚停机就被无新事唤醒。为规则统一牺牲的是主体性，而主体性排在裁决序第一位 |
| 保留 `_park_n`，只把 `else` 退路换成 `park_anchor()` | 未实跑 | 吞信洞同样闭合、改动最小（一行），但隐藏内存还在；`daemon.py` 模块头得加例外条款 |
| 把会话前基线写进 `session_end` 行（精确且可重启恢复） | 未实跑 | v2.8.71 提案的原形（`opening_n` 进 `session_end` 行，实施时改住机器文件），v2.8.77 整机制退役——机器游标的一整类状态与时序洞；为一个窄窗口重新引入不值 |

## 6. 取舍（明知的）

1. **重启后可能多一口**：停机那口若是被信叫醒的（信在上一口收尾之后、停机口开始之前
   到达），重启后账上分不清读没读 → 多唤一口。方向是噪声，且只发生在重启之后。
2. **驻留两处 + 一条不变式**：放弃了 v2.9.46「驻留只有这一处」的形态，换来进程内零
   内存且「一信恰一口呼吸」不变。不变式由 e2e 把守：循环顶的锚改回收尾行 → S11 红；
   分支驻留删掉 → S11b 红（§4 两组负对照）。
3. **行数不是更少**：内核逻辑净 +2 行（daemon −1、daemon_facts +3）。减的是状态和路径。
4. **空转呼吸维持现状**（§3）。
