# 内核修改建议稿 v1.0 —— 零信息轮次防线（甲族）＋网关联动

**基线**：xuseek v2.9.40-opt.4（正式线现行）
**依据**：融合方案 v2（三方审核+对照实验定稿）＋甲族零信息讨论
**性质**：建议稿——采纳/修改归内核组流程，发布节奏归主人统一定夺

---

## 〇、设计总纲

代码只拦「物理零信息」（逐字节同一=数学上的零信息，判它零误判）；语义零信息（乙族）不设代码警察，交给 LLM 自察、经济信号、会话结构三件既有武器。本稿共 **4 件改动**，全部小而正交，合计约 70–90 行（含注释与测试），**不新增配置面、不新增跨会话状态、无模糊匹配**。

---

## 一、改动 1：同命令三次拒绝（主防线，治甲族①）

**插桩点**：`agent.py` 会话循环内 `_exec(tc)` 顶部（现 ~367 行，畸形 function_call 判定之前）。

**状态量**（会话级局部变量，与现有 `text_round_noticed` 同款先例，会话生灭、不落盘）：
```python
_last_cmd_fp: str | None   # 上一条执行的命令指纹
_cmd_repeat: int           # 该命令连续出现次数
```

**指纹**：`fn + "\x00" + (raw if isinstance(raw, str) else json.dumps(raw, sort_keys=True))`——逐字语义，不做规范化、不做近似（模糊匹配=误报面，风暴教训）。

**逻辑**（置于线程派发之前，被拒命令不执行）：
```python
fp = 指纹(tc)
if fp == _last_cmd_fp:
    _cmd_repeat += 1
else:
    _last_cmd_fp, _cmd_repeat = fp, 1
if _cmd_repeat >= 3:
    log({"event": "tool_repeat_reject", "tool": fn, "n": _cmd_repeat, "at": iso()})
    return fn, {"error": (
        f"该命令已连续执行 {_cmd_repeat} 次、结果相同——重复执行已被拒绝。"
        "请改变做法：若在等待外部数据，请 end_session 并预约唤醒（挂铃）；"
        "若认为结果应变化，请检查依赖或换方法。")}, "refused"
```

**要点**：
- **「连续」即重置**：中间任何不同命令执行即重置计数——check→他事→再 check 永不触发；
- **零豁免状态机**：不做「说明理由可重试」检测（实验 3/3 模型直接改道，无一例需要豁免）；
- 被拒仍占一个 function_call_output 槽（错误即结果，历史完整可回溯）；
- 并行批中同命令多条：逐条过判定，同批第 3 条起被拒（合理）。

**实验依据**：glm-5.3-flash N=20 锁定态，D 形态 3/3 立即改道（对照：不拦 3/3 复读、折叠标记 3/3 仍复读——已否决）。

## 二、改动 2：同输出递进防线（治甲族②纯文本复读）

**插桩点**：`agent.py` 会话循环，`tool_calls = [...]` 提取之前（纯文本轮判定处，与现有 `text_round_noticed` 同位）。

**状态量**：`_last_out_sha: str | None`、`_out_repeat: int`（会话级）。

**逻辑**（对纯文本轮的输出文本取 sha256[:16]）：
- 第 2 次连续相同：注入一条 user 角色本机提示（沿用现有提示风格）——
  「【本机提示】你已连续两次输出完全相同的内容。若在等待外部事件，请 end_session 挂铃；若要行动，请调用工具。」（用户角色打断=实验 C 形态，3/3 有效）
- 第 3 次连续相同：`end_session`（stop_reason=`"repeat_output_guard"`）——会话已确认在复读，结束是事实陈述。

**边界**：仅统计**纯文本轮**（无 tool_calls 的轮）；带工具调用的轮不适用（其重复由改动 1 管）。

## 三、改动 3：网关错误码映射（联动——网关喊停，内核听见就停）

**插桩点**：`llm.py` `FailoverBrain.chat` 的重试分类处（现 ~431–480 行 attempt 循环）。

**逻辑**：上游返回 HTTP 4xx 且响应体含 `"code": "ctx_loop_reject"` 或 `"code": "ctx_fuse_reject"`（fad0/c150 现行契约，c150 侧等价键 `context_length_exceeded`+`needed_est_tokens` 同列）时：
- **不重试**（区别于 5xx/超时的可重试语义）；
- 抛 `GatewayCtxReject`（新异常类，携 code/est）；
- `agent.py` 会话循环 catch 之 → `end_session`（stop_reason=`"gateway_ctx_reject"`）——下口呼吸以新对话开始，恰好落进网关逃生门（末条变化=新键）。

**依据**：11-22 实弹——网关拒了 400+ 发，调用方在冷却期内继续硬撞（n=51+）；无此映射则「网关断成本、智能体死循环不死」。

---

## 四、改动 4：X-Ctx-Warn 响应头消费（纯观测）

**插桩点**：`llm.py` 响应处理处（取 headers 一次）。

**逻辑**：响应带 `X-Ctx-Warn` 头 → `log({"event": "ctx_warn", "warn": 头值, "at": iso()})`。不判定、不干预——给「能自省的调用方」一条事实，供口内交接与治理统计引用。

---

## 五、明确不做（边界）

1. **乙族不设代码判定**：无语义相似度、无模糊匹配、无「重复叙事」检测（刚被网关猜意图连烧三次，同一坑不跳）；
2. **不设轮数/上下文硬顶**：维持 v2.9.40 哲学（"轮数是 LLM 自己的决策，封顶是部署侧的事"）——本稿拦的是零信息重复，不是工作长度；上下文物理边界归上游/网关；
3. **无新增配置面**：阈值 3 为常量（如需实验调参可用环境变量 `XUSEEK_REPEAT_REFUSE_N` 覆盖，0=关——不进 config.toml，避免配置面膨胀）；
4. **无跨会话状态**：全部状态量会话生灭——天然按智能体维度（主人定则）。

## 六、测试验收（测试台先行：9d68/0c4b）

| 断言 | 方法 | 预期 |
|---|---|---|
| 1. 第 3 次被拒 | 固定命令+固定结果的桩工具连打 | 前两次执行、第 3 次返回 refused 错误、facts 有 tool_repeat_reject |
| 2. 模型改道 | 真脑复现 5c49 形态（等一个不刷新的文件） | 第 3 次后模型换法或 end_session（实验 3/3） |
| 3. est 平顶 | 改动 1 生效后跑桩循环 | est 不再爬升（每轮仅 +错误短文） |
| 4. 连续性重置 | check→他事→check→他事→check | 全部执行、零拒绝 |
| 5. 跨会话清零 | 同命令两口会话各执行 2 次 | 零拒绝 |
| 6. 同输出防线 | 桩让模型连续输出同文本 | 第 2 次注入提示、第 3 次会话终止 |
| 7. 网关联动 | 桩网关返回 ctx_loop_reject 4xx | 不重试、会话以 gateway_ctx_reject 终止 |
| 8. 回归 | 现有 selftest 全套 | 全绿（零行为变化于正常流） |

## 八、自检：三铁律符合性

- **简单**：4 件改动 6 个状态量（全部会话级）、零配置、零跨件依赖；
- **解耦**：与网关契约仅一条（错误码映射），与 fad0/c150 互不需要对方上线即可独立生效；
- **能让 LLM 做的让 LLM 做**：机制只陈述机械事实（同命令第 3 次/同输出第 3 次/网关拒了）——一切「怎么办」由模型当场决定（实验证明它会）。
