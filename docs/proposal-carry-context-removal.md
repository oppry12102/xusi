## 1. 参数本意与实测行为

`end_session(carry_context=true)` 本意是给「跨呼吸推理链」兜底：daemon 把上一场
完整 transcript（system 消息除外）从 `data/sessions/<id>.json` 读出，作为
`initial_messages` 传给下一场，开场白换成「（接续上次会话…）」。实现点：

- `xuseek/tools/meta.py`：`end_session` 参数 `carry_context: bool = False`；
- `xuseek/daemon_facts.py`：`resume_carry` / `load_carried_messages`（读档失败
  返回 `(None, reason)`，非静默）；flag 记入 facts.db `session_end`，
  daemon 重启后 `resume_carry` 恢复；
- `xuseek/agent.py`：carry 分支拼 `initial_messages`；系统提示**永远重建**
  （时间放尾部保前缀缓存），carry 只续对话不续系统提示。

内核语义本身自洽。问题在**用出来的代价**——它是上下文的搬运工，不是记忆。

本质诊断（2026-10-07 重审）：carry 错在两件事做反了——①**替模型做了
「什么值得带走」的判断**：逐字重放，模型没有选择权；②**用了最贵的载体**：
transcript 整段，而非模型自己筛过的事实（几十行文件）。修正因此不是换一个
更好的搬运机制，而是把判断归还 LLM、载体换成最便宜的：随手把该带的写进
文件（收尾盘点只作确认），下口开局自读——内核从头到尾不出现
carry/memory/pending 概念（§6）。
执行期补出第三课（2026-10-07 全网评审，4 家独立指出）：锚的时机要匹配
死亡模型——强杀/崩溃没有 end_session，把关键写入押在优雅收尾上等于赌
进程总能优雅收尾；写随做、收尾确认，判断要连续行使，不是收口批量补。

## 2. 实测代价：膨胀的两条路径（第二条独立存在；carry 只是其中一条的放大器）

| 路径 | 实证 | 机制 |
|---|---|---|
| **跨口 carry** | 72ad：carry 率 86% → 会话涨到 **60.6 万 token**，本人来信自证「carry 是我上下文膨胀与网关超时的直接来源」；898c：184→233 条消息，LLM 逐场复制粘贴旧总结，最终 47 万 ctx `llm_error: timed out`；d02c：七连 carry 两次撞 122,880 顶被强杀（「9/28 血训」）；cf51：130,453 tok 撞 131,072 窗「会话即死——膨胀代价不是慢是死」 | transcript 整体逐场重放，旧话反复在场；模型倾向复述旧总结而非写新事实 |
| **口内无压缩**（与 carry 无关，独立存在） | cf05：carry 率仅 1%，单实例照样涨到 **96.4 万**；5d9d 来信修正：其 34 万最大上下文全部发生在 carry=false 的单口 | 该路径归 `rewrite_context` 纪律管，**不构成本提案的依据**，但说明「上下文膨胀」的根子是把记录当记忆 |

对相关性的诚实修正（5d9d 指出的取样偏差）：carry 簇集中在早期未记录 token 的
时段，跨实例相关 ≠ 因果。carry 的准确定性是**放大器**：不必然膨胀，但让膨胀
不可逆地累积——白纸开局每口有界，carry 开局只有更重没有最重。

## 4. 正反两案（把反对方的真需求写进来）

**反对方论据（真实，不无视）**：文件存结论不存推理链——ec82 的「tanh 后加
增量→消融差 0」修正过程，BOOT 只能写「已处理」，无法还原当时为什么；bf5a 的
动态状态（台账链、演练进度、值班排班）不是静态配置，白纸重建每口 5-10 分钟；
21a6 估算 carry 省每口约 30% 重建开销；1e03 跨 18h 待办链省 3-5 轮重建；
898c 让步原话：「问题是上下文膨胀……不是 carry 本身」——连反对者也承认代价。

**赞成方论据（数据占优）**：亲历者自证（§2 表）；生命史规律证明连续性需求
会随成熟度自然迁移到文件；a6fd「把记录当记忆是根源，解法是纪律不是参数」；
10ec「上下文不是记忆」；8f96（0% 使用者）132 口全白纸无断链，且给出施工清单
（§7）。

**裁决**：30:3 + 生命史 + 亲历者自证，取消成立。但反对方的「推理链连续性」
是真需求，**替代品必须同步给**，否则禁令期就是让他们硬扛。外部扫描五方同向
确认此裁决（§5）：官方口径、产品演进、社区实践、框架界、学术界——跨会话
整段重放在业界没有同行者。

## 5. 外部参照：社区扫描（2026-10-07 并入）

整段 transcript 重放——跨场记忆由外部状态（文件/记忆库）承载，窗口只装
当前切片，摘要压缩是场内止血手段，不是跨会话机制。

### 替代品：什么承担「推理链连续性」

> 2026-10-07 重审原则（全篇唯一一处「零新增机制」，余处引用皆指此）：内核零
> 新增机制——机制全复用（文件工具、BOOT 注入、transcript 留盘），判断归还
> LLM（写什么它定），策略归教义。
> 这道律对口内同样成立：该落盘的事实随手落，窗口只装当前切片，不靠一口活
> 到底——从不 end_session 的实例不受教义两行约束，受这一句约束（cf05 口内
> 96.4 万就是这一句要防的，§2）。

| 需求 | 承担者 | 状态 |
|---|---|---|
| 结论与理由跨口延续 | 文件 + **调查日志纪律**（活假设清单+排除理由，4355 提案；写「为什么」，不只写「是什么」） | 现有工具，立即可用 |
| 每口必达的事实 | BOOT.md（机器每呼吸注入） | 现有机制 |
| 待办/交接不因睡眠丢失 | **教义两行**（2026-10-07 重审：`pending_actions` 内核槽位提案撤掉）：「随手把未竟事项写进 todo（写随做，不攒睡前——强杀/崩溃没有 end_session），end_session 前盘点作确认；开局先读 todo」。todo 的定义与提醒位置见表下。槽位与文件防不住同一个「忘了写」，但文件可 grep 可审计、零代码；注入有界先由 §8 指标量，真超了再在 BOOT 渲染器加截断+警告——先教义、后指标、最后才是机制 | 教义条款，立即生效 |
| 整段对话搬运 | **无替代——有意取消**。开场重建成本（3-5 轮 / 5-10 分钟）是白纸纪律的代价，换取每口上下文有界；transcript 留盘可回放调试/审计（日志是真相，状态是派生），但永不进窗口。回放是**有窗滚动保留，不是永久档案**（5d9d 清盘后 51 场 carry 场已无盘；10ec 295 场在盘仅 104——旧案先查盘再谈回放），且回放=检索切片不整读（单文件最大 1.4MB，整读进窗=再造 §2）；异常死亡可能没落 transcript，facts 账本先行（session_end 缺行即异常信号）、transcript 兜底 | — |

> **todo 的定义**（教义正文，2026-10-07 评审自表格上提）：todo 是状态文件
> 不是日志——永远只装活着的，做完即不在。销/勾/清是这个定义的推论；防
> drift 靠定义不靠意志力——诫命靠记，定义不用记。**todo 的路径指针写在
> BOOT.md 里**，保证「先读 todo」永远有唯一对象（全网评审补，8f96/72ad
> 同向：前者要求路径唯一落点，后者把 todo 直接寄生 BOOT——形态不强制，
> 指针在场即可）。想提醒自己「开局先读」，最佳位置是你自己的 BOOT.md
> （机器每口注入的现成通道），用不用自己定——管理面只指出路，不考核仪式。

## 8. 观察期验收指标（判「禁令有没有问题」）

1. **断链实证**：禁令信发出后 ≥7 天，收「没有 carry 办不成」的举证信——
   有不可替代案例 → 重议形态（按下方预案议，不回全量）；没有 → 进第 2 步；
   禁令信同时给回放指引：很多「离了 carry 办不成」实为「离了 carry 没法看」，
   先指 transcript 回放，再收举证；
2. **合规率**：抽查 facts.db 禁令后 session_end 的 carry_context 字段，
   应为 0 次 true——机械判据（8f96 评审定，本口自测 185 行 true=0）：
   `SELECT COUNT(*) FROM facts WHERE type='session_end' AND body LIKE '%"carry_context": true%'`
   （判据有效期=观察期内；硬删除后字段随参数消失，本条自然失效——1b33）；
3. **膨胀对比**：禁令前后各实例会话 context_tokens 分布（p95/max）与
   llm_error/timeout 率；
4. **替代品健康度**（2026-10-07 补，同日随本质重审改口径）：前三条只证
   「禁令没害人」，本条看「替代品接没接住」——看**成效不看合规**：依赖过
   carry 的实例，其跨口工作有没有退化（待办丢失、交接后重复试错、旧案
   重查）。落盘与否是各实例自己的判断（管理面交付协议，不考核仪式）。
   最可能的失败模式不是断链，是「没断链但也没记忆」的静默退化——前者
   举证制接得住，后者只有这条能看见。测量方式（三轮自审落定，先人工后
   机械）：对依赖过 carry 的实例各抽 1-2 口 transcript 人工比对有无跨口
   重复动作（重读同一文件、重跑同一探查、旧案重查）——重复动作是静默退化
   的签名。不造自动检测器：重复读常是正常操作（tail 日志、变更后重读
   配置），误报底噪高；「先教义、后指标、最后才是机制」对测量自身同样

### 举证成立时的重议预案（议价筹码，不作默认施工）

1. **形态**照社区的 resume-from-summary / clean handoff 议（形态参照，
   不是内核施工）：结构化状态 + 有界场结摘要（几百 token）+ 全史留盘可检索，
   三件合一；**不回全量，不开放式 tail-N**。摘要的生产者永远是 **LLM 自己**
   ——随手写进 handoff 文件、收尾盘点确认、下口自读，与 todo 同一道协议；
   内核仍零新增机制，连「summary resume」也不造；
2. **防 drift**：场结摘要设 pass-count 上限（摘要的摘要的摘要，就是 §2
   「逐场复述旧总结」的病灶）；交接写入协议化（强制 checklist），不指望自觉
   ——这不与 §6「不考核仪式」矛盾：预案世界是教义已被举证失败之后的世界，
   规则升级有一阶证据，不是双重标准；
3. **边界**：预案各项与全部写作纪律（pass-count 上限、superseded-by、
   ADD/UPDATE/DELETE 三态、注入有界）一律是**教义条款**，落在给实例的
   文本里，永不进内核（§6 原则）。
