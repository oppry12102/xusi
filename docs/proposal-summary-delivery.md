## 1. 本质诊断

三个事实把问题钉死：

1. **898c（会话重复总结事故）的病根是收件人不明**。transcript 时代总结随车重复
   投递、层层堆积；carry 退役后歧义仍在——大脑若抱着「我总结了，下口会看到」的
   心理模型，醒来发现什么都不记得，要么翻自己的存档（最贵载体），要么每口重写
   （循环靠心理模型即可存活，不需要 transcript）。
2. **BOOT 膨胀史 = 通道饥荒，不是纪律失败**。零动作注入通道只有一个（BOOT 快照），
   三个变化速率的内容（身份/新近/状态）挤一个通道，「全塞进去」是 LLM 的理性策略
   ——写别处等于赌未来的自己记得它存在。膨胀到不可用后才建 xmem/amem 分层，
   治的是症状（注入过多），病根是通道缺失。
3. **需求已被独立发明**。记忆研究 agent 在 xmem 里自造 state 标签（每口重写一条、
   取最新 k=1）——收件人明确的「新顶旧」槽是真实需求，缺位就会被发明。

## 2. 定义修正

**summary = 大脑写给下一口自己的交代。** 一口一封，新顶旧，送达即耗尽（内容层面），
存档永久留底（记录层面）。

carry 三关安检——它不是 carry 复辟：

| 检查 | carry（已退役） | summary 送达（本提案） |
|---|---|---|
| 内容谁定 | 内核（整卷重放，无筛选） | LLM 自己写，内核一字不增删 |
| 载体 | 全 transcript（最贵） | 一行声明，长短由大脑定 |
| 内核角色 | 记忆管理者 | **邮差**——送一封收件人是自己的信 |
| 寿命 | 累积（场场叠加） | 槽不是流：新顶旧，送达即耗尽 |

898c 的物理基础随定义消失：每封总结只描述一口，送达即死，无可重复。

## 3. 三通道分工（一个时间常数一个通道）

唤醒时的大脑缺的不是历史，是三个不同变化速率的答案：

| | **BOOT** | **summary** | **todo** |
|---|---|---|---|
| 回答什么 | 我是谁/怎么用世界 | 刚发生了什么 | 现在该干什么 |
| 寿命 | 慢变量（月） | 一口一封，新顶旧，送达即耗尽 | 做完即不在 |
| 谁写 | 大脑 | 大脑（end_session 收尾） | 大脑（随手，写随做） |
| 谁运 | 内核注入快照（32K 大声墙） | 内核运送（信槽文件→开场注入） | **无人运**——文件常在，指针在 BOOT |
| 谁读 | 每口自动 | 每口自动 | 开局自读 |
| **尺寸律** | ≤身份复杂度 | ≤一口工作量 | ≤活着的件数 |
| 自检法 | 「三个月后还对吗？」 | 「这是给刚醒的我的简报吗？」 | 「这事完了吗？」 |

**尺寸律是核心不变量**：每个通道的合法尺寸由时间常数决定，不由历史决定。由此得到
可观测的虫子探测器——**哪个通道只涨不跌，就是有内容住错了地方**（BOOT 当年就是
这么坏的；todo 天然自剪）。

## 4. todo 的历史归属：转场不是销毁

「做完即删」从不丢历史——完成的条目走转场：

```
接活→增条→做完→从账上划掉→进 summary（本口交代：做完了什么）
    →下口读到信（零动作送达）→需要跟进再立条 / 值得留沉淀 xmem/playbook
```

最近完成 = summary 本职；更早 = 存档/facts；结论 = xmem/amem/playbook。
大脑若想要 running done 列表，自己开文件——教义管 todo 的**语义**（状态文件只装
活着的），不管文件布局；探测器同一句管所有文件。

## 5. 账本轻量律：正文不进账本（四审定案）

四审推翻三审一处设计（summary 全文进 session_end 行）。管理员质询「facts_tail
既然读得到，为何还要注入」牵出两条律：

1. **开场白租金律**：开场白是 messages[1]，每轮重发、全呼吸携带（唯一重置=
   rewrite_context）——注入内容是每口的固定租金，只配装「落笔判定过的前提件」：
   索引行、BOOT 快照、信（8K 墙封顶）。mail 全文永不注入（外部内容、尺寸不可控、
   判断在读取方）。
2. **工具结果同理**：tail 读进的行从读入时刻起同样全呼吸携带——行肥 = 呼吸肥。
   正文（mail/outbox/summary 全文）进账本，等于每次 tail 给呼吸加租。三审的
   「先例」论据收回：mail/outbox 全文行不是正确性证据，是「重字段禁入」原则
   被违反的现场（遗留违例清单见 §11，另案迁移）。

定案法则：**账本行装事实与元数据（何事/何时/多大量），正文的法定住所在文件。**
（七审收窄为真形式：**账本不投递**——投递物不进账本，归档性正文可进；见 §11 改判。）

注入与指针的分际由此定准：**看收件人有没有行动能力**。信的收件人是「还没做任何
决定的下一口」——失忆者在第一次落笔前就该拿到前提，零动作注入是唯一保证；其余
一切（mail 正文、outbox、历史档案）的收件人是清醒的呼吸——给标题不给正文，读不读
是它的业务判断。tail 由此天然成为带标题栏的指针层：行回答「知道」（何时/何事/
多大/找谁），文件回答「读懂」；「多大」字段让「想读就去读」成为理性决策而非
盲目翻找。统一判断标准：**行里只装「知道」需要的，不装「读懂」需要的。**

tail 的角色随之降级定案：**从运营通道降为考古工具**。清醒前提三件套全在注入
（BOOT/信/索引行），续接靠 todo 自读——正常路径上无人需要读账本。todo 接不走
剩下的班，分际在**谁在场**：todo 是大脑写自己见证的意志（前向），账本是机器/
世界写大脑不在场时的事件（后向：死后来的 mail、死因、早醒）——记账人当时
不存在。唯一保留的内核义务：脏死一行（见 §6.1，同收件人失能判据）。检验法：
**把 tail 从世界上删掉，呼吸照样活得好**——运营职责清空，剩下的全是自愿考古。

summary 据此改走**信槽文件** `data/letter.md`（机器自有数据目录，breath.json 同族）：

- 收口时 _persist_session 写入（存档先行不变；写失败 stderr 响亮）
- 开场白从信槽注入（mtime 作 at；8K 大声墙照旧，原文在信槽/存档不动）
- session_end 行只记 `summary_chars` 元数据
- 槽语义由文件结构性保证：覆盖写=新顶旧；空=删文件=无信；重启安全=文件在盘
- 信的历史全文仍归会话存档（本就在 result 里）——翻历代信从「账本翻行」降为
  「存档考古」，罕见事件换 tail 每口轻装，值得
- 三审「空信整槽替换」语义平移到信槽：最新声明（含空声明）整槽胜出
- 兼容性更简：信槽是新文件，旧内核不写不读；降级=旧内核无视该文件，无害

## 6. 送达机制（施工清单）

### 6.1 改动面

- `tools/meta.py`：end_session 的 summary 描述改「写给下一口自己的交代（下口开场
  送达；新顶旧；空=不送）」
- `tools/meta.py`（顺手改真话）：send_mail 描述删去从未兑现的「追加
  data/outbox.txt」——现状是归档 outbox 行，迁移后才是文件
- `agent.py`：_persist_session 捕获声明原值（6.2 陷阱），写信槽 `data/letter.md`
  （覆盖写，空=删文件；存档先行不变）；session_end 行只加 `summary_chars` 元数据
  （账本轻量律：正文不进账本）
- `daemon_facts.py`：opening() 读信槽拼「上口交代」段——纯读（契约不变），空=无段；
  超墙大声截断（照 `_BOOT_HARD_CHARS` 先例，8K，原文在信槽/存档不动）；信头 at
  取文件 mtime（停机数月后醒，「上口」不失真）；索引行附条件脏死一行——
  最近一次收口为 breath_residue（晚于最近 session_end 行）则加残留标注
  （age_s + 存档有无——residue 行无机内死因，机器只报事实）：脏死=信可能
  是上口没更新的旧版，这行就是标注信的保质期（纯读可判，无游标状态；
  机器报自己的事，与「事实 N」同族）
- `selftest.py`：四查——送达（下口开场含交代）、新顶旧（两口后只现第二封）、
  空不出现、截断墙响亮；另加脏死行一查；README/架构文档计数 639→644
- `seed.py`：唤醒配方「读尾看上口结局」一句降为可选（信与异常已在开场，
  tail 已是考古工具）——随本版顺手改
- 管理面：kernel-upgrade.md 语义节一行；教义一句（随下次升级信/补信投递）：
  **「BOOT 装换了大脑还对的话；summary 只交代本口；todo 随手记账——接活即增条，
  做完即删（做完的事由信交代）。哪个只涨不跌，就是住错了地方。」**；
  agentops/agent_routes「索引已瘦身」注释补一句；账本轻量律 + §11 迁移案指针
  记入管理面文档（随下次统一升级，不急）

### 6.2 实现陷阱（审核发现）

**信=显式声明，不做兜底替身。** agent.py 现有 `final_text = result.get("summary")
or final_text`——summary 空时 final_text 会兜底成「最后一条助手文本」。若落账取
final_summary，没写交代的大脑会每口收到一封它没写过的假信。必须捕获 end_session
声明里的原值（空=不送），兜底逻辑只服务存档观测。

### 6.3 内核不动的

system prompt（信进开场白不进系统提示——跨呼吸前缀缓存保住）；todo 零概念；
xmem/amem、playbook、seed 三层配方（通道补齐后大脑自己会挪，它的世界它做主）；
观测台读存档照旧。

## 7. 死亡模型

- 干净死（end_session）→ 交代信送达
- 脏死（崩溃/强杀）→ breath_residue 行（死因+存档指针），翻不翻档归大脑
- 第三种死法 rewrite_context → todo 锚在动作时（写随做），账不陪葬

两种死法两封信，锚时各配其死（第三课同源）。

## 8. 否决的替代方案

| 方案 | 否决理由 |
|---|---|
| summary 并入 BOOT（每口重写交代段） | 槽退回纪律约束；append 比 overwrite 省事，膨胀机制复活（§1.2） |
| summary 并入 todo | 一口一命 vs 做完即不在——寿命不同，必有一个被污染 |
| todo 保留最近完成段 | 最近完成 = 信的本职；状态文件混日志 = 每口重新计算派生状态 |
| system prompt 注入信 | 每口可变内容破坏跨呼吸前缀缓存 |
| 指针制（开场只给路径自己取） | 要自己取的信 = 没人读的信，通道名存实亡 |
| 内核写 handoff 文件进 workspace | 机器碰大脑世界的文件——所有权违例 |
| summary 参数退役 | 898c 病根不除；「对外报表」也不是它的定义 |
| 完全不送达（只靠大脑自律写文件） | 参数在 schema 里而不送达=参数撒谎；自律槽在 BOOT 上=诱惑面复原，在 xmem 里=多一次动作且住错层（§1.3 已实证需求） |

## 9. 四原则审核

**简单** ✓ 机制只有一跳：声明→信槽文件→开场注入。无新工具、无新配置；账本行只多
一个元数据字段（summary_chars）。
诚实记录：8K 截断墙的数值是猜的，但响亮性是不变量、数值可调——先例同款。

**解耦** ✓ 三通道各守一个时间常数，互不渗漏；内核新增的只有一条邮路（与 sleep/stop
同构的声明运输）；opening 纯读契约不变；信不进 system prompt，前缀缓存无恙。

**不过度设计** ✓ 对照「完全不送达」认真想过（§8 末行）：需求已被实证（§1.3），
参数已存在（schema 在场），送达是让现有表面变诚实的最小机制——不做才是浪费。
诚实记录：at 时间戳是 10 字符的便宜诚实，若嫌多可去掉，不影响骨架。

**能让LLM做的就让LLM做** ✓ 写不写、写多长、写给谁看——全是大脑的（空=不送）；
内核不解释、不筛选、不留游标；todo/xmem/amem 零概念。内核里多出的唯一概念是
「收尾声明随账本过桥」——运输基础设施，不是记忆管理。教义只立重力（尺寸律+探测器），
不管布局与格式。

**审核结论**：一审通过（6.2 假信陷阱折入）；二审补 CLI 边界（§10）；三审对接面
通过（空信整槽语义，平移入信槽，§5）；**四审（管理员质询「tail 既可读为何注入」）
推翻三审一处设计**——确立账本轻量律，信改走信槽文件，双投递随之消失；mail/outbox
全文行登记遗留违例（§11）。无未决项，可施工。

## 10. 风险与守门

- 大脑把状态塞信（summary 变伪 todo）→ 两口后状态消失，自罚可见且可自纠；
  教义一句钉住分工
- 长信注入成本 → 8K 大声墙 + 「大件走文件、信里留指针」阀门
- stop 后数月才醒 → 信头带 at
- facts_tail / /v1/facts 响应变胖 → 诚实数据（行里装的就是大脑说的），观测面自便
- CLI 直跑（`xuseek.sh run`）不走 daemon 开场，收不到信（二审发现）——人在场的
  手动档，管理员即收件人；信件通道归节律呼吸，已知边界，不动
- **双投递——四审已消除**：信走信槽文件，session_end 行无正文，tail 不再带回
  同一封信；每口到达恰好 1 次（开场注入）
- **开场白租金律**（四审立，§5）：注入内容全呼吸携带（messages[1] 每轮重发）——
  开场白只装索引行、BOOT 快照、信；mail 全文永不注入（外部内容、尺寸不可控，
  判断在读取方）
- **存档与信槽的写入窗口**：写序=存档先行→信槽，之间崩溃则信未落但存档在——
  下一口收不到信 + breath_residue 指路存档，与脏死同构，可接受

## 11. （七/八审改判）「账本不投递」为律——迁移案撤销，队列不可省

七审推翻四审的迁移案。「正文不进账本」写宽了：它管的真实伤害是**经账本投递**
（信：行作载体→每口注入 + tail 双投递，已由 summary.md 根治）。mail/bell/outbox
全文行不承担投递——投递走队列，行只是归档（读者：观测台 SQL、自愿考古），伤害
从「每口被迫交租」降为「考古自愿一读」。

**律重述：账本不投递。** 投递物（要主动送到眼前的：信、待读件）不进账本；
归档性正文（事后才有人读的）可进账本。此形式下零违例、零例外表——比
「一条律 + 一张违例清单 + 一个迁移案」简单。复杂度的大头不是机制，是宽律
制造的未来工程；撤案即减负：

- 原五处「地基」原样不动：观测台信箱视图（读行）、转发桥（扫行）、xusi 投信、
  bell 全文双写、seed 回查句——全部照今天工作
- 唯一已做的修正是 meta.py 描述改真话（v2.9.28）；「data/outbox.txt」永不创建
- mail/bell 双队列保留：停机驻留时「管理员信是唯一唤醒者」的政策由两个文件
  结构化表达——合并单 inbox 就得解析行内容定政策，反而复杂

**（八审）队列文件不可省**——「大脑在 todo 记处理到哪行」被否：

- 一个文件换两个游标：大脑持久游标（每次读后必记，写错=静默跳信，错无回声）
  + 机器瞬态基线（唤醒用；重启丢基线→早醒失效，到点才看见）
- 队列文件的「空」就是游标：文件系统代管，一次截断，零簿记，崩溃安全——
  **数字会漂，空不会骗**
- 本质：账本 append-only（历史），投递是可销毁态（未读→已读）——两种语义不可
  同屋；队列文件=可以被清空的账本，存在恰因账本永远不清。考古游标（n 自己记）
  写错顶多重读，无害，可交大脑；投递游标错=漏信，必须结构化
- 分工终局：未读→队列（可销毁）｜未办→todo（债务清单，不混簿记——尺寸律
  ≤活着的件数）｜历史→facts.db（只增+归档腿）｜意图→BOOT/summary.md

**（九审）「单一一次性门铃」被否**——来信/bell 的本质确是唤醒，但那只是瞬间
使命；第二使命是**追讨**（持续到转化完毕）。一次性铃的三个洞：醒了≠办了，
铃已消费→忘了转化即静默丢失（队列=转化闸的执法者，无限重试）；内容只在
facts→每口醒来重读 tail 心算差分（队列只装未读增量，销毁即提交）；队列是
机器唯一可验证的投递态，删了它 daemon 对投递失明又得造基线游标。写侧
「都写 facts + 按铃」已是现实（channels.append 一次两写）；铃管「叫你」
（一次性），队列管「等你办完」（追到转化为止）——两个寿命，不可合并。

**（十审）nag 与「能让llm判断」不冲突——判定：追讨保留。** nag 从不逼人办事
（「办不办」100% 归大脑）；它守的是**决定必须显式发生**：每件来信以显式决定
结束（办/todo 条/清空=决定不办），不能以「睡着」结束。三个出口全是大脑的
动作；机器检查「清了没」，不检查「判了什么」——连「不办」都尊重（清空即
合法不办，nag 永不再响），只拒绝让「不办」通过遗忘发生。判断权在大脑的样本
已在系统：停机驻留=大脑亲写的唤醒政策（只让老板叫，铃闭嘴）；sleep_seconds=
大脑自己表达债的调度。todo 管**决定之后**的调度，队列管**决定之前**的不丢，
零重叠；撤掉追讨→「清了但忘了转化」窗口大开（错无回声，与八审拒绝投递
游标同款错误形态）。nag 是判断完备性的最低保障，不是机器抢判断。

## 12. 全景走查：睡眠到醒来（目标态）

**家当**：BOOT.md（身份快照，注入）｜letter.md（信槽，覆盖写=新顶旧）｜
mail.txt/bell.txt（队列，领取后清）｜facts.db（纯账本，只增无人必须读）｜
sessions/（存档，只增）｜todo（大脑自记自读）｜xmem/amem（沉淀）。

end_session(sleep_seconds, stop) → 存档 → session_end 行（v2.9.27 原状）→ 睡，
mail/bell 早醒；脏死则信是最新一版（不陪葬），residue 行标注「可能过期」。

## 14. 六审定稿：文件直写（信不过内核的手）

五审后又退一步：BOOT 早就是「大脑自有文件 + 内核注入」，summary 何必要走参数
这节管道？参数制让内核经手信（接参数→捕获→写槽→空删→记尺寸），还养出 §6.2
兜底陷阱。文件直写一刀全免：

  覆盖写=新顶旧，醒来即见（内核注入）。路径由开场索引行给（绝对真路径，与
  mail 同族——索引行只报机器独有数据）
- **内核的唯一记忆机制 = 开场注入两份大脑自有文件**：BOOT.md 必注（慢变量），
  summary.md 有则注（新近）；一条代码路径，缺文件即跳过；todo 无人运，指针在 BOOT

  清理）——参数是旧运输管道，留着=一个槽两个写者；退役后 end_session 形状即

- **脏死反而更好**：写随做的信不陪葬（最新一版总在盘上）；residue 行照旧标注
