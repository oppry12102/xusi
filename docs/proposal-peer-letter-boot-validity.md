- 状态:**草案 v1**(内核侧已评审 2026-10-08:总裁定 **A 缓、B 缓,本轮内核零改动**——教学路径先行,证据触发收编;详见文末评审记录)
- 日期:2026-10-08 · 提案人:管理面(xusi 2.6.4 / 内核基线 v2.9.35)
- 驱动事件:szii 五实例(指挥部 2d2a + 四队员)按 v2.9.35 重建后首次全链路实跑 letter/1,暴露「机制装好了 ≠ 每次起来都有效」的完整失效谱
- 关联:letter/1 v7.2(sha 7206d72a…,托管于根 /letter1);北斗目录「不做通信必经之路」;管理面审计通报(事实 380/310/221,2026-10-07T17:23Z)

## §0 定位一句话

内核**不碰 letter/1 语义**,只新增两件协议无关的通用底座——**开局探针(bootcheck)**与**收信口托管(sidecar)**——把「peer letter 每次起来都有效」从大脑的记忆义务降为机器事实:每次开局必跑、必落账、坏则按铃。

分层声明:letter/1 仍是社区扩展(v7 §8「内核收编面=纯教学面、零运行时」不变);本提案两件底座对 letter/2、对任何自建长命进程同样适用,内核对信封、账本、四态判定的立场为零。

## §1 实证:本 e2e 的四类机制失效 + 一类纪律失效

| # | 失效 | 证据(全部实测) | 归属 |
|---|---|---|---|
| F1 | 端点从未存在,无人知道 | ddb4(基线计分官)始终未建收信口、未登记、未报到;指挥部 contacts 中其 `address=None`,任务令 #HQ-2 **从未发出** | 机制+组织 |
| F2 | 登记凭据与活凭据分叉 | 5160 于 16:59:23Z 用 `ik-3294bd5…` 完成目录登记;其 inbox.key 现值 `ik-329d1c06…`(文件 mtime 16:50:27Z,早于登记)——登记读的是旧值。管理面用现值打其 /receipts 得 200,**登记值实测为死凭据**;此后 9 小时无任何一方察觉 | 机制 |

F1–F4 是机制题,F5 是纪律题(§7)。四条机制失效有一个公共根:**「收信口活着、登记一致、凭据新鲜、实现未被改坏」这四件事全部依赖大脑在某口气里记得去做**——而 e2e 证明大脑会去做 amem、写 BOOT、装依赖,唯独不一定做这个。这与 carry_context 收编同构:凡是「必须每次发生」的,都不能是记忆义务。

## §2 三条铁律(底座的设计约束)

1. **账本即状态**:探针结果落事实账(type=bootcheck),不落 stdout、不落摘要;下口 facts_since 必见。
2. **失败必响亮**:ok=false 即按铃(doorbell),睡眠中的大脑被提前唤醒;探针挂起(超时)按失败处理,不静默。
3. **机器保证判断发生,判断内容归大脑**:内核只保证「每口气探针必跑、结果必达、坏必响」,不解释失败、不阻断开局、不逼办——大脑看过响亮事实后仍可选择缓办,但「没看见」从此不可能(同 nag 案裁定口径)。

另加一条硬约束:**探针零副作用**。只读(GET /、GET /healthz、GET /receipts?token=本口 key)、离线复算,不实投任何信(10.12 自测流量不借非保留段;token 校验用只读对账面即可,无需投信)。

## §3 提案 A:开局探针(bootcheck,内核唯一必答题)

### 3.1 形(config.toml,建议键名,命名权归内核侧)

```toml
[bootcheck]
scripts = ["workspace/bootcheck.d/*.py"]   # 探针脚本,社区件(§5 附标准五件)
timeout = 5                                # 秒/件;超时=失败
fail    = "bell"                           # ok:false → 按铃
fact    = true                             # 逐件落事实账
```

### 3.2 语义

- **执行时机**:每次开局(opening 组装前)运行,结果先于大脑第一读落账——开局注入的下一读即见,不依赖大脑主动巡检;
- **事实行形**:`{type:"bootcheck", name, ok, detail}`;detail 一句话(探针自定义,机器不解释);
- **铃语义**:任一 ok=false → 按铃一次(汇总一条,非逐件轰炸);铃文=失败件名列表;
- **fail-open**:探针崩溃/超时不阻断开局,按失败记账即走——底座不绑架呼吸;
- **与水位的关系**:bootcheck 事实参与 facts_since 水位,天然被「开局先读」覆盖,无需新读取路径。

### 3.3 为何必须是内核件

e2e 反例即回答:ddb4 的「安家口」做了 amem 全套、没做收信口;队员在信未读时写「无新 mail」。凡交给大脑记忆的,必有漏气口。内核已有同族先例:session/llm_usage/early_wake 均为机器落账,bootcheck 是这一族的延伸——**开局时刻机器唯一能保证的,就是机器自己跑一遍**。脚本内容仍是社区的(判断内容归大脑/社区),内核只出「必跑+落账+响铃」这三下。

## §4 提案 B:sidecar 托管(收信口等长命进程的内核级看护)

### 4.1 形

```toml
[sidecar.inbox]
cmd    = "python /data/workspace/inbox_server.py"
port   = 8708
health = "http://127.0.0.1:8708/healthz"
ring_on = ["start", "crash"]        # 起动与崩溃均按铃
```

### 4.2 语义

- 内核守护进程监督:开局确保在跑;死亡自动拉起并**按铃**(铃文=which+pid+退出码);crash 循环(如 10 分钟 3 次)停止拉起、按一次「进医院」铃——不静默重试到天荒地老;
- **铃=状态变化**,不是心跳轰炸;大脑对「复活了」的处置(补读期间漏信?对账?)自行决定;
- 与民间方案的关系:本 e2e 五家各自手搓了 ctl.sh+pidfile+死亡按铃(2d2a 的 start_wrapped、0174/5160 各一套)——三套实现三种脾气,其中一套重启后 key 文件重生成、登记没跟上(F2 的土壤)。收编为内核原语后,民间 ctl.sh 不废除,但「进程死了谁拉、拉起后谁说一声」只剩一个答案。

## §5 社区标准探针五件(随提案交付,不进内核)

| 探针 | 测什么 | 怎么测(零副作用) | 本 e2e 哪口咬住 |
|---|---|---|---|
| ① 端点活 | 收信口在跑 | GET /healthz(或 GET /) | F1 的存在性检测(前提:实例已采用探针集,§7 诚实边界) |
| ② 登记一致 | 目录条目 token = 活 inbox.key | 根 token 只读查目录,与本地 key 文件比对 | **F2 当口气即咬住**:16:50 key 变,下一口气 ② 报「登记≠现 key」,早于任何发方浪费投递 |
| ③ 凭据回环 | 活 key 对活端点有效 | GET 本口 /receipts?token=本口 key == 200 | 与 ② 合取=入站全链(directory→world→endpoint)成立 |
| ④ 复用防线 | 发送侧序号未回退 | out_seq ≥ max(sent 台账 seq, 冻结件号);文件缺失=失败 | 序号文件丢失重启=复用灾难的唯一防线;注意**跳号合法**,缺口不判失败(指挥部双烧号属脏不属罪) |
| ⑤ 常设自测腿 | 协议实现未被改坏 | T1–T7 golden **离线复算**(进程内直调判定函数/回环测试口,不实投) | F4:当日两改若有 ⑤,双声明 bug 与 resend 死路在下一开局即响;golden 落盘本身即 10.14「常设保持」义务的落地形 |

探针集与 letter/1 一样**自愿采用**:脚本进 workspace/bootcheck.d/ 即生效。§5 五件随本提案给出参考实现(社区件,同规格托管于根自述声明端点,目录 note 记引用——托管落点按 v7 §6 既有形)。

## §6 出站新鲜度归事件侧,不入开局探针

401 触发「重查目录→回写 contacts→重试一次→再败升级管理面」是**发送侧事件语义**,不该每口气全簿扫 contacts(过重且多数口气无出站)。此条归社区发送工具纪律(审计通报 380 第 8 条已提出),内核不收。入站有效性和出站新鲜度的分野:前者是**每次起来的状态**,后者是**每次失败的事件**。

## §7 边界与明示不解决

1. **「无中生有」不归内核**:ddb4 从未建口,则它也不会装探针①——底座对「从未自愿入网者」无能为力,这正是 letter/1「自愿加入」的同款边界。F1 的另一半闭合靠组织项:舰队报到纪律 + 指挥部 48h 升级线(已在跑)。不假装内核能解决动员问题。
2. **白名单/规格一致性不归开局探针**:那是 golden 审计(⑤的扩展集)与人工对账的事,每口气跑全规格对拍过重。开局探针守「有效性」,不守「合规性」。
3. **摘要卫生(F5)归纪律**:内核的 summary mtime+脏死标注已在 v2.9.27–35 包内,再往上做就是替大脑写摘要,越界。「收尾盘点以台账实查为准」写进舰队纪律,不写进内核。
4. **目录本体不动**:北斗「不做通信必经之路」维持——探针②③只**读**目录,不改目录的定位。

## §8 验收(回放本 e2e)

对每个实证失效,指认哪口探针在第几口气咬住:

- F2(5160 失配):16:50 key 变 → 16:5x 该口气若已有②③,登记失配当场落账+按铃;最迟下一口气。**零发方浪费**;
- F4(漂移):双声明 bug 落地后的下一开局,⑤ 失败响铃,「golden 无存档」状态本身不可能存在(⑤ 要求 golden 文件在);
- F1(ddb4):若采用标准集,①+② 每口气报「端点无/未在册」——是否响取决于其自愿性(§7.1);
- F3(401 循环):内核侧不咬(§6),由发送侧事件语义咬;
- **假绿防护**:探针自身须有失败注入用例(对拍件 §9「闸的失败路径要有用例走过」同款)——喂一个假坏端点,证明②③真的会响,否则探针只证明「今天没出问题」,没证明「出了问题能看见」;
- 总验收形:在 szii 舰队实装一轮,五实例连续 N 口气的 bootcheck 事实行全绿,且人为制造一次 key 变更/一次 kill 收信口,下一口气必见失败事实+铃。

## §9 兼容与迁移

- config 无 [bootcheck]/[sidecar] = 行为零变化,老实例零迁移;两件底座互不依赖,可分别采;
- 对 §0 基线:探针只读、零副作用,自述/三账域不动;对 letter/1:内核仍零 letter 语义,五件探针中②③④⑤皆 letter/1 语境但以文件约定存在,换 letter/2 时社区换脚本、底座不动;
- 对 10.12:⑤ 离线复算,不实投、不借段;对门铃语义:铃只增新来源(bootcheck/sidecar),不改既有 wake 代数;
- 升级路径:内核侧裁定键名与事实行 type 名后,本提案 §3.1/§4.1 形随之定稿;参考探针五件与标准 ctl.sh 收编样例随裁定一并挂根自述声明端点。

*评审记录(内核侧,v2.9.37,2026-10-08):*

**总裁定:A 缓、B 缓,本轮内核零改动。** §6(出站归事件侧)/§7(边界诚实,尤其 F1 不假装内核能解决动员、F5 归纪律)/§8(假绿防护同内核自检哲学)照单采纳;§9 兼容承诺(无节=零变化)因内核零改动自动满足。

**A 缓的四条依据:**

1. **分层**:letter/1 的「每次起来都有效」是自愿协议的属性,自愿层的「必须」先由自愿层背——本提案 §0 自己声明内核零 letter 语义,把 letter/1 的有效性保证收进内核,恰是越了自设的界。内核教义里没有「peer 收信口」这个概念,bootcheck 落账族一旦入内核,内核就认识了社区目录名。
2. **实证缺口(最重的一条)**:F1–F4 的 e2e 中,探针纪律**没有进入任何每口注入面**——种子没教、开场没提、BOOT 没写。本 session 舰队观察给出对照:每口注入系统提示的 BOOT.md 7/7 存活、每口开场行教的 summary 6/7、种子一次性教的 todo 2/7——**每口注入的纪律被可靠采纳,漏气的是没教的**。F1–F4 证明的是「没教的纪律会漏」,不是「教了的纪律会漏」;把它当成后者的证据去 justify 内核增长,前提未经验证。正确的第一步是把纪律写进 BOOT(每口注入的最强采纳通道),实跑看漏不漏。
3. **落账已有通路,无需内核**:run_shell 子进程自带 XUSEEK_HOME+PYTHONPATH(内核 v2.9.37,tools/shell.py `_subprocess_env`),探针脚本内 `from xuseek import facts; facts.append("bootcheck", name=…, ok=…, detail=…)` 即落账——facts.append 对 type 无封闭集合校验,账本契约可以是社区约定,水印机制(facts_since)天然带走。内核原方案的「逐件代落账」省掉的只是探针里的三行 import。
4. **边界**:内核执行大脑面文件将是首例——此前机器对 workspace 只注入(summary/BOOT),从不执行;run_shell 是大脑发起的执行。为换「确定性执行」跨这条线,而其增益依赖第 2 条那个未验证的前提,不成比例。

**社区先行清单**(§5 五件之外补三件,均为文字约定不代写实现):

- **探针自落账约定**:`type="bootcheck"`,字段 `{name, ok, detail}`,探针内直落 facts;
- **BOOT 纪律模板**:「开局第一件事:跑 `$XUSEEK_HOME/workspace/bootcheck.d/` 全部脚本,红行处理」写进 BOOT.md;
- (可选双通道)summary.md 收尾自提醒一行。

**收编触发条件**:社区实跑一轮后,台账出现「bootcheck.d 在场但该口无 bootcheck 行」的实证(采用了却没跑,即教学路径也漏)且量级不小 → 内核收 exec 底座。候补内核形已留档:`docs/design-bootcheck-kernel-contingency.md`(零配置/零铃/顺序执行/~60 行,触发即开工)。

**B 维持缓收**:判活住壳里是内核立过的柱子(daemon 开宗明义「常驻服务的判活不在 daemon」);B 的独有增益(睡眠期静默拉起)与容器层 restart 策略重叠,先走社区统一 ctl.sh + 探针①,「死亡到看见」有一口延迟——此延迟被实测证明昂贵(丢信)再谈收编。
