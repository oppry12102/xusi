# 提案：同文连发守卫（idle_loop_guard）——会话层空转的机械收口（v2.9.53 候选）

- 状态：**建议稿，候主人批**（2026-11-26）
- 提出与管理面分析：管理员会话（9b82 循环案深挖引出）
- 证据样板：tx-bj-1 agent-9b82 会话 20261126T003811Z（facts 行 64135–64245 + fad0 网关账 63 笔时序）

## 一、问题：会话层空转——第二起同类案

### 案一（11-20，04f6）：工具循环
同一命令重复 1,906 次，烧 6.4 亿 tokens。当次处置后落地三层防线（命令指纹批注 / 400K 软告警 / 950K 硬保险丝）——**都在网关与账本层，会话层无守卫**。

### 案二（11-26，9b82）：待命循环
无任务的呼吸（事实账水位无新行）→ 会话 73 轮、19 分钟、238 万 tokens，其中 **49 轮输出几乎一字不差的待命散文**（「收到。会话继续，我保持待命……若需结束本次呼吸，请我使用 end_session」）。最讽刺处：模型**每一轮都用文字说该调 end_session，却 49 次未发出工具调用**，直至第 73 轮才真正调用。

### 两案同构

| | 04f6 | 9b82 |
|---|---|---|
| 循环物 | 同一命令的调用 | 同一文本的回复 |
| 共同点 | **机械可检测的重复**（哈希相等），内核会话层无守卫 |

### 现场机制还原（9b82）

1. 空呼吸醒来，无事可做；
2. 模型输出待命散文（贪心解码+相同上下文前缀 → 确定性复读）；
3. 散文被追加进上下文 → 前缀更强 → 下一轮输出一模一样 → 自我回声；
4. 每轮 payload +2.3K 字符精确增长（21K→195K），completion 恒 492 tokens；
5. fad0 尾指纹第 12 次报警（ctx_loop_hit）——网关是路由器，无权杀会话，只注记；
6. 第 73 轮模型自发调用 end_session，循环自愈。**若它没有自愈，会话无机制上限**（9b82 `limits: None`，max_rounds=0 不限）。

## 二、根因与层级

### 2.1 v2.9.50 已杀死的：呼吸层空转

「空转呼吸退役」（睡基线=入睡时刻账尾 max_n，睡后新行才醒）焊死了「会话结束后当场再唤」的循环——呼吸层的空转已死，9b82 案中呼吸层工作正常。

### 2.2 会话层：显式留给大脑纪律，而纪律会失守

v2.9.50 明文：「会话中途已到行的时效归大脑收尾决策，收尾前看一眼账是它既定的 todo 纪律」。内核会话收口条件仅三种（源码自证）：end_session 工具调用 / 预算到顶 / 错误。**纯文本回复不收口、轮数不限（机器不替大脑思考）**。

9b82 的收尾纪律在那一口失守：它看了账、复述了「无新行」、却没执行「空转即收」。

### 2.3 空隙

会话层缺一个**不依赖大脑自觉的机械守卫**。可用的机械信号（零内容理解即可判定）：

- 连续 N 轮**无工具调用**；
- 连续 N 轮**回复文本哈希相同**。

两者同时成立 = 原地踏步的机械定义，与「950K 保险丝按 token 数拦调用」同族——**机械信号上的机械守卫从来都是内核的合法领地**（主人 11-26 判词：「新内核就是干这个的」）。

## 三、定案方案：同文连发守卫

**连续 5 轮满足「本轮无工具调用 且 本轮回复文本哈希 == 上轮回复文本哈希」→ 内核强制 end_session，stop_reason=`idle_loop_guard（同文连发×5）`，facts 归档一行 `idle_loop_guard` 审计（含轮号与哈希）。**

- N=5 的理由：给合法短待命留足余量（低于 5 有误伤风险），又远早于 9b82 的 49 轮（浪费截断在 1/10 处）。可config化（limits.max_idle_rounds，缺省 5）。
- 「无工具调用」是必要条件：**带工具调用的轮不算**——合法的重复劳动（逐条处理队列、每轮都动工具）永远不触发。
- 哈希取回复正文（剥空白后 sha12）——正常对话两轮正文完全相同的概率≈0。
- 触发即收口，**不是错误**：stop_reason 标注 idle_loop_guard，facts 留档，下一口呼吸照常调度——大脑醒来看到审计行自会明白发生了什么（与 950K 熔断同款事后可读性）。

### 设计原则

**机械信号上的机械守卫是内核的合法领地，内容判断永远不是。** 守卫不看模型在说什么（零信息纪律），只看它是否在原地踏步（哈希+计数器）。950K 保险丝按 token 数拦、tail_sha 按 fingerprint 注记、本守卫按同文连发收口——同族三层，各有其闸。

## 四、已否决的备选

| 备选 | 否决理由 |
|---|---|
| 仅 BOOT 教养（空转即收一句话） | 教养是软约束——9b82 案证明它会失守（模型知道纪律却 49 轮没执行）。教养保留为互补（§六），不做唯一防线 |
| 按员配 max_rounds 上限 | 钝器：不检测空转，到轮数硬切（可能切在任务正酣处）；且需逐员配置，漏配即裸奔 |
| 网关熔断匿名重复调用 | 网关是路由器无会话管辖权；且署名员（9b82 有卡有署名）同样会循环 |
| 内容判断（关键词/LLM 评审「这是不是空话」） | 直接违反零信息纪律——机器读内容判定语义，即「替大脑思考」 |

## 五、与其他防线的分工（全景）

| 层 | 防线 | 管什么 |
|---|---|---|
| 网关 | 尾指纹 n=12 注记 + ctx_loop_hit 账本 | 早期信号（跨会话可见） |
| 网关 | 950K 硬保险丝 / 400K 软告警 | 单笔与近窗体量 |
| 网关 | latency_guard / timeout 300s | 慢调用沉底 |
| **内核（本案）** | **同文连发×5 强制收口** | **会话层原地踏步（机械判定）** |
| 大脑 | 收尾纪律 + BOOT「空转即收」教养 | 第一道自觉防线 |

四层各自独立、互不替代、事后可读。

## 六、实施清单

1. `xuseek/agent.py` 会话循环：轮末检测（无工具调用 && 正文 sha12 == 上轮）计数 ≥5 → 强制 end_session（stop_reason=`idle_loop_guard`）+ facts 归档；
2. `limits.max_idle_rounds` 可配置（缺省 5，0=关闭——尊重例外场景）；
3. seed BOOT 增一句教养：「无任务时立即 end_session，不复述待命状态」；
4. selftest：正例（同文×5 强制收口）+ 负例×2（带工具调用的重复不触发、正文略变的重复不触发）；
5. e2e：空转场景档（无任务呼吸 → 守卫收口 → 审计行在账）。

## 七、验收标准

重演 9b82 案：构造无任务会话+恒定回复 → 第 5 轮强制收口、stop_reason=idle_loop_guard、facts 审计行在账、下一口呼吸正常调度。负例：带工具调用的连续轮 20 轮不触发。

## 八、残余风险（如实）

- 正当的纯文本同文连发（如连续确认多条排队消息）会被误收——但下一口呼吸即可续，代价一次重启呼吸；发生频度由 facts 审计行监控，误伤多了调 N 或关守卫；
- 守卫只治「原地踏步」，不治「换着花样空转」（每轮正文微变的空转哈希不同）——此类靠教养层与网关注记兜，真出损失再加那条具体的闸（零机制纪律：不为想象中的敌人预付复杂度）。
