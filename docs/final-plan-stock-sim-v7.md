## 主人定调（008 直达 · 优先级最高 · 本稿吸收）

**不可动的立场铁律**（沿用立项定调，全程不动）：
- **活下来 > 跑得快**（控制回撤优先于追逐收益）。
- **三可**：可回溯 / 可演进 / 可升级。
- **两块地基不动**：撮合引擎纯代码（确定性账本）、调度器不干预 LLM。

**设计四原则**（主人 008 直达；凡与四原则冲突处，**含本稿历史收敛点**，一律以本意见为准）：
1. **简单**——能省就省，砍冗余的字段、通道、仪式。
2. **解耦**——组件职责单一、互不越界。
3. **无安全过设计**——只为真实失效模式设防，不为想象中的风险堆砌。
4. **能让 LLM 做的就让 LLM 做**——判断归 LLM，确定性计算归代码。

**评审目的**：搭架构、写 mission、定策略、定协议、定未来演化进步的机制。

**智能体数目**：按需求来，**不设上限也不设配额**（本稿各阶段数目是「按需建组清单」，非配额上限）。

**四原则合规结论（逐章自查）**：终稿**无结构性冲突**——确定性计算（撮合 / 账本 / 信用分机械结算 / 链校验 / 降级表 / 熔断通道）归代码，判断（市场状态 / 题材 / 决策 / 风控软判断 / 归因描述）归 LLM，两者边界即「解耦 + 可审计」，非「过设计」。凡与四原则冲突的历史收敛点（含提案原文），已以本意见为准改写；被否旧主张连同理由见 §十四 异议存档。

## 三、核心协议 / schema（定稿统一版）

**情报单**（组员→PM，永不入引擎）：
`signal_id, group, group_version, brain, subject, symbols[], view(人读散文), direction(long/short/neutral), score_0_10, confidence(整数1-10), horizon(枚举1d/3d/5d/1w), invalidation(必填结构化·机器可校验), evidence(必选≥1), market_state, schema_version, group_seq, expires_at, issued_at`

- `invalidation` 必填且机器可校验（价格/量能/家数阈值），出具时注册到引擎，模糊自然语言条款拒收。
- `expires_at` 为**权威保鲜窗**：引擎侧 received_at + TTL 盖章为准，不信 LLM 时钟；隔夜/跨午休语义成文；过期情报 PM 静默丢弃不入加权。（`ttl_minutes` 已删，信息量由 expires_at 承载）
- 乱序以 `group_seq` 为准。

**决策单**（PM→引擎）：
`decision_id, prev_decision_id, ref_signals[], snapshot_seq, target_positions[{symbol, weight, urgency, reason}], cash_floor, valid_until(引擎received_at+TTL盖章), max_single_weight, sector_cap, max_chase_pct(可选), risk_verdict{verdict, by, checked_at, note}, market_state, brain, group_version, issued_at`

- `prev_decision_id` 链式引用：**永指最新链环（无论 pass/veto）**——被否决单也是链上一环；风控否决单抄送引擎登记为「已否决」链环；引擎校验链连续，失配 = 拒单 + 原因码，打回 PM 重取重出，不静默丢弃。
- `snapshot_seq`：引擎每发持仓快照盖单调 seq，决策单引用之（弃 hash——JSON 规范化依赖键序/浮点/空白，跨实现易碎）；快照失配 = 拒单 + 原因码。
- `valid_until` 引擎侧 received_at + TTL 盖章，不信 LLM 时钟。
- `max_chase_pct`（默认 2%）：由引擎换算限价，保护意图保留、价格生成归代码（删 limit_price，职责归位）。
- `urgency` **三值**：`open_auction / intraday_event / close_auction`（纯执行窗口语义）。「盘后签发次日预案」的执行窗口 = 次日 open_auction，由「盘后签发 + 次日 open_auction + 隔夜/跨午休 TTL」覆盖（共识 3 已成文），故不设 eod 档。

## 四、信用分机制（定稿全套）

1. **confidence 整数 1–10** + 锚定纪律：冷启动前 20 交易日固定 5/10，之后锚定本组近 60 日命中率 ±1，PM 侧超锚截断（+0.15）。
2. **计分对称**：s = ±2 × (c/10) × 实现度（实现度：≥3% 记 1 / 1.5–3% 记 0.5 / <1.5% 记 0.2）。
3. **防洗分**：invalidation 触发仍按触发时点方向盈亏计分（错方向 + 易触发条款 ≠ 免罚）；证伪纪律分 +0.2 单列不冲抵（**周演化会批量人工裁定**，机器判必被 trivial 条款刷分）。
4. **聚合**：分组信用分 = 指数衰减加权均值（半衰期 30 交易日），按 4 市场状态桶独立记账，桶内 <10 样本向全局分 shrinkage。
5. **版本冷启动**：版本更替先验 = 上版近 20 日均值，不清零。
6. **对抗性验收**：作弊组刷 confidence 致权重升 = 验收失败。
7. **PM 加权（乙丙 2:1 定稿）**：**w = clip( softmax(credit), 0.5×均权, 2×均权 )**——softmax 连续校准，clip 保每组话语权下限（乙：至少半票，信息多样性保底）且输出硬界对任意输入异常完备兜底（丙复核：单组极端分不会拉爆归一化）。信用分全组统一 1–10 锚定标尺，无跨组量纲。信用分只影响话语权，**永不进风控硬规则**。
   - *可选增强（存档 §十四，主人可裁启用）*：合流案 `w = clip(softmax(z-score(credit) ±3σ winsorize), 0.5×均权, 2×均权)`（甲 z-score 内核 + 丙 winsorize 前置护栏）。008 原则①③下未采：统一标尺下 z-score 消量纲前提不成立，winsorize 守护的失效模式已被 clip 输出界覆盖。
8. **权威账纯代码派生**：信用分从事件日志 SQL 派生，LLM 不碰权威账；信用分文件是缓存、可全量重算（审计 = 重放），attr 只做结算触发/人读日报/异常标注。
9. **子机制 P1 实测后按实效精简增补**：信用分各子机制（锚定参数、实现度分档、聚合窗）于 P1 实测后按实效精简增补——凡实测无区分度的子机制即删，演化机制（原则④）保证其可演进。

## 五、硬约束与风控

- 硬约束显式进决策单：`max_single_weight` / `sector_cap`（可选字段，缺省读风控配置），风控只做软判断 + 一票否决；**现金下限 20% 不可破**；不确定就降仓。
- 决策单必带 `risk_verdict` 签章。
- **brain 字段**：情报单/决策单记实际产出模型（实例自报）；归因按 `(group, group_version, brain)` 三元记账——故障转移不再糊涂账。
- 引擎权限白名单：决策单只收 PM 登记地址 + token；情报单只入 PM、永不入引擎。
- `market_state` 打标单一来源 = 环境组长发布 + 调度器归档时间戳；桶边界滞回防抖动。

## 七·五、网络拓扑与双根治理（v6 修正案 012 + v7 修正案 013）

**立法意图**：对外联络是特权不是默认。双根 = 在 oppry 域登记、被该域智能体**找到**并**双向通信**；取数 = 单向**消费** oppry 现成服务，**不是双根诉求**。013 主人指示增设对外联络员 liaison——**岗位新增，非判据推翻**：012 双根判据不变，liaison 四职责（a019 联络 / WebUI 展示 / 服务经纪 / 获批外交）全是判据内诉求，双根名额 0 → **1**。

**A. 双根判据与名额（= 1，liaison 唯一双根岗）**

判据成文（可复用，未来新岗照判据自判，不再开一轮评审）：
> 双根唯一判据 = 运行时必须被 oppry 域主动找到（双向通信）——即对外提供服务或跨域协调。单向消费 oppry 服务（取数）不构成双根诉求。

逐岗核（env×3 / theme×3 / PM / 风控 / 归因 / 演化 / 个股 / S1 / S2 / base-keeper）：全部为内环岗，对外动作只有 outbound 直连消费 oppry 服务（消费不需「被找到」）；告警主人走内网目录通道（010 已钉）。**唯 liaison 满足判据**（四职责均为「被找到 + 双向通信」诉求），**当前双根名额 = 1**。

机制保留：双根 = 实例 `playbook/根智能体.json` 的 `roots` 数组含两对条目（北斗 4dd8 + oppry 4a2f）；登记义务、token 门纪律全部保留成文；未来新增双根岗（对外服务岗）走 §十 签批报主人批名额。

**B. 根 token 保管（liaison 唯一持有 · 六钉）**

oppry 根 token = 全域钥匙。**全舰队唯一持有 = liaison**（其余 15 岗 0 持有不变）。六钉：
1. **唯一持有**：仅 liaison 的 roots 含 oppry 根 token，其余 15 岗 0 持有不变。
2. **用途限定 + 审计**：仅「登记 + 被找到应答」（含换址重登 / token 轮换重登）；查目录 / 写目录 / 签发服务 token 全禁（3:0）；全部对外通信落日志 + 审计（外联观测闭环覆盖 liaison）。
3. **服务 token 最小授权点对点分发**：管理员在签约时点把该服务 token 直发消费岗，liaison 全程不经手服务 token 值。
4. **值不入文**：根 token / a019 凭据 / WebUI token / 各服务 token 永不进自述、信件、文档、日志。
5. **分发与轮换**：管理员随出生配置分发、轮换再分发；失守即撤换 + 告警主人。
6. **缺位处置**：liaison 缺位时经纪职责停摆待补（记 §六 降级表）；根 token 不转移任何他岗——例外不可继承。

经纪 = 无钥信息职能（发现/谈判/对账）：服务发现走免 token 公开端点（`GET /directory_key_names`）+ 附录 A；签约与服务 token 分发走 §十 + 管理员点对点最小授权。v6「0 持有」精神（持有面最小化）以「唯一持有 + 查目录全禁 + 无钥经纪」形态完整平移。

**C. 数据消费链路（直连，不设本地岗；v6 §七·五 C「token 走登记通道」条款同步修订留痕）**

外部数据消费一律直连 oppry 域在册服务（ip+port+token），舰队不设本地取数或中继岗；消费侧发现数据异常按 §六 降级表处理并标注。

**D. 全员通用条款（三禁止 · 白名单式；liaison 唯一豁免「对外联络」）**

> 不得访问 oppry 域在册服务以外的公网资源；不登记公网根；不对外提供服务。

（替换 v5 三禁止——原「不直接访问公网源 / 不发公网请求」与全员直连 oppry 消费冲突，白名单式自洽。）
